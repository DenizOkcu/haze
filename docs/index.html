How it works

Ask

Describe the outcome in plain language. Attach a screenshot or mention the files that matter.

Watch

haze inspects the project, edits files, runs commands, and streams compact tool activity.

Review

Get a concise summary with changed files, validation commands, and honest failure status.

What is included

  • File and code tools

    Discover, read, search, edit, and write files. Workspace boundaries and ignored files stay explicit.

    ✓ grep      createSession  12 matches
✓ readFile  src/session.ts 184 lines
✓ editFile  src/session.ts +8 -3

  • Commands and dev servers

    Run foreground commands or keep up to five managed background processes with bounded logs.

    ✓ bash     npm run dev
  background-1 running on :3000
✓ process  output background-1

  • Durable sessions

    Resume a workspace conversation, fork an earlier session, or compact long-running context.

    $ haze --continue
✓ resumed  api-service
  18 messages, context restored

  • Reusable skills

    Save project or personal workflows as Markdown and invoke them with commands like /code-review.

    /skills  add deploy-check
✓ created
  .haze/skills/deploy-check/SKILL.md

  • Parallel workers

    Delegate independent work to isolated subagents with bounded concurrency and serialized writes.

    /fleet migrate four packages
✓ web     ✓ admin
✓ mobile  ✓ cli

  • Headless operation

    Use haze -p in scripts with text, JSON, or streaming JSON output and reliable exit status.

    $ haze -p "audit auth" --output json
{ "status": "complete", "findings": 2 }

Common questions

Does haze require a hosted account?

No. Install the CLI, add an OpenAI-compatible endpoint, and choose a model. Local endpoints can run without an API key.

Can it work on an existing project?

Yes. haze reads your repository instructions, respects nested context files, and uses the current workspace as its mutation boundary.

Does it ask before every tool call?

No. haze keeps guardrails light and lets the model work through a task without repeated permission dialogs. You should still supervise consequential changes.

Where are sessions and settings stored?

Settings live in ~/.haze/settings.json. Durable sessions live under ~/.haze/sessions, with private file permissions.

Run haze in your project.

Install the CLI, open a project directory, and type haze.
