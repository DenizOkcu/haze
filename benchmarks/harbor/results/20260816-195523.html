Method and Limits

This is a single-task diagnostic run, not a statistically meaningful leaderboard. The operational anomalies matter as much as the reward.

Task Contract

Implement one dependency-free Node.js CLI that parses CSV, filters rows, selects columns, performs stable lexical sorting, and returns precise error codes.

  • One Harbor task: csv-query
  • One primary attempt per harness
  • One local haze follow-up (fixed build) from commit 41b1efa
  • Model requested: glm-5.2
  • 17 pytest checks per artifact

Result Semantics

Harbor runs the verifier even after an agent exception. This correctly distinguishes artifact quality from harness reliability.

  • Reward 1.0 means all verifier tests passed
  • Exception means the agent command did not exit cleanly
  • Corrected Pi completed cleanly with reward 1.0
  • The fixed haze build completed cleanly with reward 1.0, superseding the two earlier timeout exits

Known Confounds

Version pinning and provider metadata do not guarantee identical backend execution across adapters.

  • Claude and Pi response events identify glm-5.3
  • nanocoder exposes no token usage
  • Pi required a private Compose overlay for key injection
  • The haze follow-up ran under a 10-minute process timeout it did not reach
  • Earlier haze builds never promoted shell checks to validation evidence; the fixed build records purpose=validation results

Recommended Next Run

Make Pi credential forwarding permanent, verify model identity at the response level, and run at least three attempts per harness.

  • Separate clean-completion and verifier-pass metrics
  • Scope summaries to the current timestamp
  • Normalize usage accounting where possible
  • Retain exact package versions and endpoint IDs
  • Record the provider-reported response model in every adapter trajectory
