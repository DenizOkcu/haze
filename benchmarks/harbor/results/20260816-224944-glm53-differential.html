The failed shell call (134.0 s) is the recovery loop working, not a defect. The model wrote a 23-case scratch assertion script; one case compared against a literal placeholder in the script itself. haze surfaced the non-zero exit as structured failure (260 ms), the model pulled the full output via readToolOutput (bounded-output retrieval doing its job), diagnosed its own script bug, re-ran corrected validation at 170.9 s — and the completion gate only accepted the final after that passing evidence. Verifier later confirmed 17/17 independently.
Context discipline: per-step input stays in a 3.5K–12K band across 11 steps (total 92K cumulative, 67% served from cache). The 84-second step-3 “think” produced the whole implementation in one writeFile — no thrashing, no rewrite cycles, one surgical editFile afterward. Mutation count for the whole goal: 2.

06Incident log · pi first attempt (benchmark infra, not pi)

harbor 0.20.0’s built-in pi adapter does not forward ZAI_API_KEY. Its provider→env-key allowlist (anthropic, openai, groq, google, …) has no zai entry, so the key never reached pi’s container. pi exited in ~1 s with No API key found for zai → trial recorded reward 0.0 via NonZeroAgentExitCodeError. This is a false negative for pi, so the cell was rerun with the known workaround (a docker-compose overlay injecting ZAI_API_KEY, matching the earlier csv-query-pi-key job): rerun passed 1.0 in 149 s.

Action item: patch run-benchmark.sh to attach the pi auth overlay permanently, and/or upstream the zai key mapping to harbor. Classified provider/infra-side; excluded from the harness failure matrix.

08Interpretations & caveats

  • No differential signal against haze. All four harnesses passed; no haze-only failure, no missing envelope, no infra failure attributable to haze. Under the benchmark protocol this cell produces zero fixes for 1.0.0.
  • Efficiency class: haze’s token discipline (fewest input tokens, 67% cache hit, no rewrite thrash, 2 mutations total) is genuine harness behavior — same model, same task as the 549K-token claude-code run. Its wall-time is second, not first, because step 3 spent 84 s composing the entire implementation in one pass (a correctness-friendly trade: one write + one edit vs nanocoder/pi/cc’s multi-bash iteration).
  • Architecture visible in the trajectory: parallel tool batching (steps 1–2), bounded output + retrieval (step 7), evidence-gated completion (final accepted only after step 10’s passing shell), goal supervisor idle as designed (1 cycle). All 0.11.0 headline behaviors exercised, none misfired.
  • Token columns are not cross-harness comparable: cache-read inclusion differs (haze/pi/cc include it; nanocoder reports nothing; cc additionally bills $0.79). Compare deltas within a harness across runs, not absolute numbers across harnesses.
  • n = 1 per harness. Per the protocol, differences at this sample size are anecdotal; the release gate requires 3 attempts per cell plus two consecutive clean weekly differentials before tagging 1.0.0.
  • Model attribution: provider served glm-5.3 for a glm-5.3 request in every haze step (per-step responseModel recorded) — no drift this time.
