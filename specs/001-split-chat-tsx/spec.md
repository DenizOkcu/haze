# Feature Specification: Split chat.tsx

**Feature Branch**: `[001-split-chat-tsx]`

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description: "Split `chat.tsx` (905 lines) — the one file already flagged by your own repo rules. Pure maintainability, reduces agent context load, no UX change. Lowest-risk, highest-conformance next step."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Maintainer Reads a Focused Chat Component (Priority: P1)

As a maintainer (human or agent) working on the interactive chat screen, I want the chat UI split into smaller, cohesive modules so that any single concern (input handling, transcript rendering, command handling) can be read and edited without loading a 905-line file.

**Why this priority**: This is the entire value of the feature — maintainability and reduced context load. Everything else is a constraint on doing it safely.

**Independent Test**: Open the split modules and the original `chat.tsx` side by side; confirm every exported behavior of the chat screen is preserved and that no module exceeds a fraction of the original size. Verified by `npm run typecheck && npm test && npm run lint` passing with no behavioral test changes.

**Acceptance Scenarios**:

1. **Given** the current 905-line `chat.tsx`, **When** the split is performed, **Then** the chat screen's rendered output, keyboard handling, and command dispatch are byte-for-byte equivalent in behavior.
2. **Given** the split modules, **When** a maintainer opens any one of them, **Then** the module is small enough to hold in context without truncation.

---

### User Story 2 - End User Experiences Zero Change (Priority: P1)

As an end user of the haze CLI, I want the refactor to be invisible: identical chat behavior, identical rendering, identical keyboard shortcuts.

**Why this priority**: "No UX change" is an explicit requirement; any user-visible regression is a failure of the feature.

**Independent Test**: Run the CLI before and after the change; the chat screen renders and responds identically. Existing UI/transcript tests pass unmodified.

**Acceptance Scenarios**:

1. **Given** a running chat session, **When** the refactored code is used, **Then** streaming output, tool groups, task bar, input draft, and slash-command behavior are unchanged.
2. **Given** the existing test suite, **When** it runs against the refactored code, **Then** no test requires modification to pass.

---

### Edge Cases

- The split MUST NOT change module import cycles or introduce new circular dependencies between UI modules.
- Props/state lifted out of `chat.tsx` MUST keep identical types; no `any` introduced (repo ESLint forbids it).
- The dynamic-tail row budget, static transcript, and resize replay behavior described in AGENTS.md MUST remain intact — these are load-bearing transcript invariants.
- Generated `dist/` output MUST NOT be edited; only `src/` changes, with `dist/` regenerated by build.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The chat screen component currently in `chat.tsx` MUST be decomposed into smaller single-responsibility modules under the existing UI source tree.
- **FR-002**: All existing behavior of the chat screen (rendering, input, commands, streaming tail) MUST be preserved exactly; no user-facing change is permitted.
- **FR-003**: The refactoring MUST be verifiable by the existing checks: `npm run typecheck`, `npm test`, `npm run lint` MUST all pass without weakening any assertion.
- **FR-004**: No new dependencies, no new public APIs, and no changes outside the chat UI subtree are in scope.
- **FR-005**: Each resulting module SHOULD be substantially smaller than the original 905-line file so a single module fits comfortably in an agent's context window.

### Key Entities *(include if feature involves data)*

- **Chat screen component**: the top-level interactive chat UI previously contained in `chat.tsx`; after the split it composes smaller modules.
- **Chat UI sub-concerns**: input handling, transcript/static output, dynamic tail (streaming roots, tool groups, task bar), command dispatch — each becomes its own module.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: The largest module in the chat UI subtree is reduced to well under half of the original 905 lines.
- **SC-002**: `npm run typecheck && npm test && npm run lint` pass on the refactored code with zero test modifications.
- **SC-003**: No user-visible behavior change: chat rendering, keyboard handling, and slash commands behave identically before and after.

## Assumptions

- The split is a pure internal refactor; no new features are introduced (YAGNI).
- Existing tests already cover the chat UI behavior sufficiently to catch regressions; no new tests are required for a behavior-preserving split.
- Module boundaries follow the existing `src/ui/` conventions (plain TypeScript/React per AGENTS.md); no new framework or abstraction layer is added.
